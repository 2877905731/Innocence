# Innocence Windows 自适应桌面体验

## 1. 核心决策

Windows 端不再定义为“一个可以被拉大的桌面挂件”，而定义为一套 **自适应桌面画布（Adaptive Desktop Canvas）**。

窗口拥有大、中、小三个连续响应的主界面层级，以及一个用户主动进入的悬浮球状态：

1. **大画布 Large Canvas**：接近 Codex 一类高效桌面工作台，承担完整功能与深度操作。
2. **中画布 Medium Canvas**：默认启动形态，信息完整但更聚焦，适合长期停驻在桌面一侧。
3. **小画布 Small Canvas**：接近 QQ 紧凑窗口的信息密度，单列、快速切换、适合陪伴与即时操作。
4. **悬浮球 Focus Orb**：接近系统功能中心的最小入口，只表达状态与快速返回，不承载完整业务页面。

大、中、小是同一个应用在不同窗口空间下的重新编排，不是把同一个页面机械缩放。悬浮球是独立的终端状态，不由拖拽缩小自动触发，防止用户误操作后丢失上下文。

## 2. 设计原则

- **默认不小**：首次登录默认使用中画布 `920 × 760`，不以挂件尺寸启动；以后恢复用户最后一次非悬浮球窗口尺寸与位置。
- **内容重排，不做缩放**：文字、按钮和触控目标保持舒适尺寸，空间不足时改变导航、列数、面板层级和展示优先级。
- **状态连续**：调整尺寸时保留当前页面、筛选、输入、滚动位置、计时状态和未提交草稿。
- **高级感来自秩序**：依靠比例、留白、对齐、动效节奏、材质克制和信息优先级产生品质感，不依靠过度透明、圆角或装饰堆叠。
- **一套结构，四套主题**：侘寂禅意、极简主义、中世纪现代主义和玻璃态只替换设计令牌与局部装饰，不改变四种窗口层级的核心信息架构。
- **用户尺寸优先**：允许自由拖拽；只有进入稳定断点后才重排，避免窗口在临界尺寸频繁跳动。

## 3. 窗口层级与尺寸

| 层级 | 进入条件（逻辑像素） | 推荐/默认尺寸 | 主要用途 | 窗口策略 |
|---|---|---|---|---|
| Large Canvas | `width ≥ 1180` 且 `height ≥ 720` | `1360 × 860` | 深度规划、统计、团队、管理、并列上下文 | 普通可缩放窗口，可最大化，不默认置顶 |
| Medium Canvas | `width ≥ 760` 且 `height ≥ 620` | `920 × 760` | 默认桌面陪伴、计划与专注主流程 | 普通可缩放窗口，可选择置顶 |
| Small Canvas | `width ≥ 380` 且 `height ≥ 520` | `460 × 700` | 快速查看、消息、计划、专注操作 | 紧凑可缩放窗口，可吸附屏幕边缘 |
| Focus Orb | 用户主动收纳 | `72 × 72`（随 DPI 在 `64-88` 调整） | 状态提示、恢复窗口、快速开始/暂停 | 无边框、可拖动、边缘吸附、可选择置顶 |

### 3.1 断点规则

- 断点按窗口**客户区**逻辑尺寸计算，不按显示器物理像素计算。
- 必须同时满足宽度和高度条件；宽而矮的窗口降一级布局，避免内容被垂直挤压。
- 在每个断点设置 `32px` 回滞区（hysteresis）：进入新层级与退回旧层级使用不同阈值，减少拖拽抖动。
- 大、中、小之间使用 `160-220ms` 的布局过渡；遵循 Windows“减少动画”系统设置。
- 小画布达到最小尺寸后停止缩小；继续拖拽不会自动变成悬浮球。

## 4. 四种形态的信息编排

| 功能区域 | Large Canvas | Medium Canvas | Small Canvas | Focus Orb |
|---|---|---|---|---|
| 全局导航 | 左侧固定导航轨 + 顶部命令栏 | 紧凑导航轨，可折叠为顶部栏 | 顶部当前模块 + 底部 4 项主导航 | 无导航，单击恢复 |
| 当前专注 | 主画布固定可见，支持并列详情 | 首屏主卡，可展开详情抽屉 | 顶部核心卡，保留开始/暂停/结束 | 进度环 + 状态色 + 剩余时间简写 |
| 今日计划 | 主区列表/时间轴，可并列编辑 | 主区列表，编辑器覆盖或右侧抽屉 | 单列优先队列，一次突出一项 | 不展示列表 |
| 统计 | 右侧上下文栏或独立页面 | 摘要卡 + 独立页面 | 单行摘要，点击进入 | 仅通过环形进度表达当前状态 |
| 好友/团队/消息 | 列表、会话、详情三段式 | 列表 + 会话两段式，详情抽屉 | 类 QQ 单列列表与会话互相切换 | 未读点，不显示消息内容 |
| 设置/管理 | 完整页面与多栏表单 | 单栏表单 + 分组导航 | 精简入口，复杂设置提示扩大窗口 | 右键/长按菜单仅含恢复、置顶、退出 |

## 5. 各层级布局规格

### 5.1 Large Canvas：桌面工作台

- 左导航轨 `72-80px`，承担首页、计划、专注、团队、消息、统计和设置入口。
- 中央主画布使用 12 列网格，最小内容宽度 `680px`，展示当前任务、计划时间轴和主业务页面。
- 右上下文栏 `300-360px`，用于当前专注、今日摘要、通知和与当前页面相关的详情。
- 顶部命令栏放置页面标题、搜索/命令入口、同步状态和窗口级操作。
- 允许主区与上下文区独立滚动，但一次只保留一个主要滚动容器，避免滚轮焦点混乱。
- 视觉目标是“专业工作台”，不是将中画布卡片简单横向铺满。

### 5.2 Medium Canvas：默认桌面伴侣

- 默认尺寸 `920 × 760`，首次进入居中显示，后续恢复用户位置。
- 使用 `64px` 紧凑导航轨或顶部模块栏；导航可按用户宽度自动切换，不要求手动设置。
- 主内容保持单一视觉焦点，次级信息进入右侧抽屉或底部可展开区域。
- 今日计划与当前专注可形成两列，但当任一列小于 `320px` 时立即回落为单列。
- 复杂二级页面仍可完整使用；必要时提供“展开到大画布”入口，但不强迫用户切换。

### 5.3 Small Canvas：紧凑交流与执行窗口

- 默认参考尺寸 `460 × 700`，最小 `380 × 520`。
- 采用单列结构：顶部窗口拖动/标题区、当前模块内容、底部 4 项主导航。
- 首页只保留当前专注、下一项计划、今日完成度和一个主操作；其他摘要通过下钻获取。
- 好友、团队和通知采用类似即时通讯软件的“列表 → 会话/详情 → 返回”结构，不挤压成多栏。
- 复杂图表、批量计划编辑和后台管理显示只读摘要，并提供“扩大窗口继续”操作。
- 小画布仍是完整、体面的应用窗口，不采用过小字号、密集边框或玩具化图标。

### 5.4 Focus Orb：悬浮球

- 默认直径 `72px`；内容为品牌标记、当前专注进度环和最多一个未读状态点。
- 单击恢复到最近一次非悬浮球形态；双击执行用户配置的快捷动作（默认开始/暂停专注）。
- 拖动后吸附到当前显示器最近边缘，保留 `12px` 安全间距，不自动遮挡任务栏。
- 右键菜单仅含：恢复窗口、开始/暂停专注、置顶开关、隐藏到托盘、退出。
- 悬浮球不展示消息正文、计划清单或复杂按钮；它是入口与状态灯，不是缩小后的页面。

## 6. 尺寸变化与状态连续性

1. Flutter 使用 `LayoutBuilder` 根据客户区尺寸计算 `DesktopPresentationTier`。
2. 页面路由与业务状态位于层级布局之上；切换层级只替换 shell 和内容编排，不重建控制器。
3. 同一业务组件提供 `full / comfortable / compact / glance` 四种呈现密度，但共享数据模型和操作回调。
4. 文本输入、编辑草稿和滚动位置使用稳定 key 保存；跨层级切换不得清空。
5. 从 Small/Medium 放大到 Large 时，当前详情进入右侧上下文栏；从 Large 缩小时，右栏内容转为抽屉或独立页面。
6. 窗口状态按显示器和 DPI 保存：最后非悬浮球尺寸、位置、层级、是否置顶、悬浮球位置和最后页面。

## 7. 原生 Windows Shell 调整方向

现有 `page / widget / mini` 命名调整为语义更清晰的：

- `canvas`：承载 Large / Medium / Small，自由缩放并由 Flutter 自适应分层。
- `orb`：承载 Focus Orb。
- `auth`：仅用于未登录流程；登录后进入 `canvas`。

实施时保留旧 mode 字符串的兼容映射，避免一次性破坏现有调用：`page → canvas`、`widget → canvas`、`mini → orb`。

原生层负责窗口边框、最小尺寸、最大化、置顶、DPI、吸附、托盘和位置持久化；Flutter 层负责 Large/Medium/Small 的布局判定与内容重排。

## 8. 主题与质感

- 四套主题共享相同的空间比例、断点和内容优先级，主题不得改变功能可见性。
- Large 使用更克制的背景和更清晰的层级，避免大面积高强度材质造成视觉疲劳。
- Medium 允许更强的品牌氛围，但主操作区必须保持高对比和低噪声。
- Small 减少装饰数量，保留字体、主色、材质和关键形状作为主题识别。
- Orb 每套主题只使用一个主表面色、一个进度色和一个状态色，确保任何壁纸上都清晰。
- 动效以位移、尺寸和透明度的短过渡为主，不使用循环漂浮、持续发光或大面积背景运动。

## 9. 前端生成参考规则

- `docs/design/templates/` 中四套 HTML 继续作为 Large Canvas 的视觉与构图参考，不要求逐行转换为 Flutter。
- Medium、Small 与 Orb 必须依据本文档的信息优先级重新编排，不能直接把 Large HTML 等比缩小。
- 如果 AI 直接参考 HTML 不方便或转换效率低，可忽略 HTML 代码，使用主题提示词、设计令牌、本文档布局规则和组件状态完成等价实现。
- 最终验收以 Flutter 实际窗口在四种形态下的可用性、舒适度和视觉一致性为准，不以 HTML 结构相似度为准。

## 10. 分阶段落地

1. **P00.5**：四层级信息架构、断点、组件密度接口和主题映射已固化并获用户确认。
2. **P01-P04**：P01 首批已落地三档 Shell 与 88×88 Orb；后续页面重建继续同步实现 Large/Medium/Small，不在阶段末尾补做响应式。
3. **P05**：在现有原生 `canvas / orb` 窗口切换基础上，完善边缘吸附、托盘、置顶、DPI 与窗口状态持久化。
4. **P06**：在 100% / 125% / 150% DPI、单屏/多屏和四套主题下完成尺寸矩阵验收。

## 11. 验收标准

- 首次登录默认窗口不小于 `920 × 760`，且完整显示首页主操作。
- Large/Medium/Small 临界尺寸来回拖拽时，无布局闪烁、溢出或状态丢失。
- 任何层级正文不低于 `14px`，主要操作点击区域不低于 `40 × 40px`。
- Large 具备完整工作台效率；Medium 无需频繁放大也能完成日常主流程；Small 可完成专注、计划、消息和通知的核心操作。
- Orb 可在 300ms 内恢复最近窗口，且不会遮挡任务栏或丢失当前专注状态。
- 四套主题在四种形态中保持辨识度、可读性和一致的信息结构。
- 键盘导航、屏幕阅读器标签、减少动画、高对比度与 DPI 缩放均可用。
