| 项目 | 实际观察 | 判断 |
| --- | --- | --- |
| CPU | 2 vCPU；load average 0.34 / 0.17 / 0.05 | 当前低负载，足够版本查询和鉴权；不在该主机编译三端包 |
| 内存 | 总计 1974 MiB，可用 963 MiB，无 swap | 可在原服务里增加版本元数据；避免额外 Java 服务、构建任务或整包读入堆 |
| 三容器 | backend 290.9 MiB、MySQL 277.6 MiB、Redis 13.44 MiB | 瞬时实际用量，不代表高峰容量或长期压力验证 |

| 公网带宽 | 用户套餐截图：上下行各 200 Mbps | 理论总吞吐 25 MB/s，实际受线路、协议和并发影响 |

**结论：现有主机可以实施“后台上传已构建、已签名安装包 → 发布版本 → 在线账号检查并下载”的首期方案，无需为此立即升级服务器。** 使用原 Spring Boot 做元数据与身份校验，Nginx 用文件发送处理安装包。该结论基于容量估算与当前快照，尚未做下载并发压测。

控制台显示 1.7/2.0 GiB 内存使用与 `MemAvailable=963 MiB` 不矛盾；Linux 有可回收文件缓存，不能直接以面板“已用”推断只剩 0.3 GiB 可用。

## 流量与并发估算

以单个安装包 **80 MiB** 估算，600 GiB 理论可下载约 7680 次；按当前剩余额度约 7662 次。若只分配剩余流量的 60% 给更新，约 4597 次，其余供正常业务和重试。实际应使用上传文件的精确字节数计算，Windows、Android、鸿蒙不能合并成一次包下载。

200 Mbps 为整台服务器上限。80 MiB 单包独占带宽的理想时间约 3.4 秒，10 个相同下载平分带宽时约 34 秒；这些是理论值，不是下载速度保证。首期建议：

- 下载总预算 80–120 Mbps，保留 API 和同步带宽；单下载约 2 MiB/s，初期目标约 5–7 个同时下载。
- 支持 Range/断点续传；客户端同一包只保留一个下载任务，失败按退避重试。
- 安装包保留最近 3–5 个稳定版本；按平台分开保留最新可回退包，磁盘可用低于 8 GiB 停止新上传并提示管理员。
- 以套餐后台累计流量为准，500 GiB 月用量预警、550 GiB 暂停新的大包下载并提示管理员；原业务请求继续可用。计费周期、控制台统计延迟和上传/下载是否双向计费还需以服务商账单规则核对。
- 用户量达到数千、发布后集中下载或主机出口长期占满时，将包存储迁移到私有对象存储/CDN，后台和鉴权契约不变。

## 后台与客户端的最小闭环

后台新增“版本发布”：平台、架构、渠道、显示版本、整数构建号、最低兼容构建号、更新说明、包大小、SHA-256、原签名身份及安装方式。上传进入草稿，完成包类型/平台/版本/摘要/签名核对后再发布，支持下架和指定稳定版本。只有管理员能上传和发布，普通用户和匿名请求分别返回 403/401；保留不含凭据的发布审计。

大包上传由 Nginx 请求体临时文件承接、后端流式写入；安装包放在 Web 根目录外。用户下载先由后端认证，再使用 `X-Accel-Redirect` 转交 Nginx internal location；普通直接访问该目录不能下载。平台安装服务如必须自行抓取 URL，则另签发绑定文件、版本和到期时间的短时下载票据，并在代理端验证，不能回退到永久公开地址。

客户端启动后低频检查，设置页提供“检查更新”。同一版本只提示一次，可稍后处理；计时运行时允许下载，**安装和重启等用户确认并先保存计时及草稿**。下载完成后核对长度、摘要与签名身份，失败不执行安装。版本比较用整数构建号，禁止按字符串比较 `1.10` 与 `1.9`。

检查接口拟为 `GET /api/app/v1/updates/latest?platform=...&arch=...&channel=...&currentBuild=...`，下载接口另按 releaseId 鉴权。认证身份来自现有会话，不接受客户端提供 userId；过期会话、平台不匹配、缺字段、非管理员发布、损坏包、生成清单失败、旧票据和断网续传均应纳入验收。

“直接发布版本”是上传已经完成构建与签名的安装包。该服务器不承担 Flutter/Android/Windows/HarmonyOS 编译，不通过替换 Dart 文件绕过平台安装流程。首期使用全量包，暂不实现差分补丁或静默强制升级。

## 三个平台分别落地

| 平台 | 可行路径 | 本项目当前前置 |
| --- | --- | --- |
| Windows | 软件内检查、下载和校验；外部更新助手在应用退出后启动现有安装器，保留用户资料，失败可回退 | 现有安装器可复用；Authenticode 仍是原 G06 待办，不能把摘要校验当作签名可信验收 |
| Android | 软件内下载同包名、原证书 APK，由用户授权来源并确认系统安装，覆盖保留资料 | 继续使用原发行证书；声明/检查安装权限并处理拒绝，不承诺任意设备无确认安装 |
| 鸿蒙平板 | 先提供账号内版本提示；应用市场版本接官方更新路径，个人指定设备包沿已核对的系统分发入口覆盖 | 当前为个人指定设备 Release Profile，公开 HAP 未签名；0121–0124只证明本人设备范围，不能当任意用户均可自建 HAP 自动更新 |

Android 的用户确认与更新所有权规则依据 [PackageInstaller.SessionParams](https://developer.android.com/reference/android/content/pm/PackageInstaller.SessionParams#setRequireUserAction(int))；来源安装授权依据 [REQUEST_INSTALL_PACKAGES 官方说明](https://support.google.com/googleplay/android-developer/answer/12085295?hl=en)。鸿蒙本项目边界以 0121–0124 的已验签指定设备资料为依据；官方[应用安装卸载与更新](https://developer.huawei.com/consumer/cn/doc/harmonyos-guides/application-package-install-uninstall)、[指定设备发布](https://developer.huawei.com/consumer/cn/doc/app/agc-help-internal-test-release-app-0000002260691994)入口在本次网页抓取中未返回可读正文，实施前须结合实际账号发布方式和本机 SDK 核对，不据此虚构可用权限。

推荐实施顺序：后台草稿/上传/鉴权下载和 Windows、Android 客户端闭环 → 受控下载验证与失败回退 → 鸿蒙按实际分发权益接入。用户确认了在线账号边界；本轮仅完成评估，未对外新开安装包下载目录，也未实现此更新模块。
