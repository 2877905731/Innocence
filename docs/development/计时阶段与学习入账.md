# 计时阶段与学习入账

2026-11-02后续部署（0150）：学习入账接口和可空幂等键/唯一索引已在生产备份及隔离恢复核对后上线，重复上报不重复累计、两个合成owner隔离及认证/权限/缺字段路径通过，合成数据已清理，注册保持关闭。本人鸿蒙已覆盖1.3.3+15，0152三端1.3.3已公开；TIMER权益、真实长时/后台/跨设备与离线导入完整矩阵继续待。范围见[个人平板更新](../releases/v1.3.3-harmonyos-self-use.md)。

2026-11-02 用户要求：

> 专注时间应该做成自定义的，番茄循环需要算进学习时间，同时不论是专注时间还是学习时间在结束后豆应该通知用户，尤其是番茄我们需要仔细拆分在学习时间完成后应该立即停止通知用户，此时用户可以点击开始进行休息，休息完以后通知用户，这样一次循环可以算作一轮，用户可以继续开始计时学习时间进行下一轮学习时间

本次覆盖《独立番茄闹钟》旧版自动循环和不入账决定：

- 专注支持直接输入 1–1440 分钟，保留快捷选项。普通专注到点结束并提醒。
- 普通专注 start 请求新增可选 `durationMinutes`（1–1440）。传入时以服务端接收时刻起算，`endTime` 保留为旧契约必填兼容字段；未传时保留原截止时刻语义。这避免 1 分钟输入因网络传输不足整 60 秒而被误拒绝。
- 独立番茄依次为学习中、学习完成等待、休息中、休息完成等待。每个阶段到点即停，不自动开始下一阶段；点击“开始休息”或“开始下一轮学习”才继续。暂停和等待均不消耗时间。
- 学习结束立即入账实际学习时长；休息结束才完成一轮。休息为 0 时学习结束即完成一轮，仍等待手动开始下一轮。提前结束只保留实际学习，不完成未结束的一轮。
- 后台恢复最多补算当前一个阶段，截断在原截止点；不得因长时间离开而补造多轮。旧时钟只迁移其当前阶段和历史轮次，不追溯生成未经记录的学习时长。
- 新入口不再创建旧的专注自动绑定循环；已有旧绑定记录仍可显示、解除或结束，保持兼容，不把旧自动阶段伪装成新手动轮次。
- 番茄学习片段按本机日期拆分并保存毫秒。与本机普通专注同时运行时，普通专注已覆盖的时间不重复入账；切换普通专注状态前结算番茄片段。原有跨设备普通专注统计规则保持。
- 本机 ownerScope 与在线 user 继续隔离；离线记录仅经既有导入预览和用户确认进入账号。在线记录按当前认证身份上传，断网保留并重试；不会将旧账号记录发给新账号。

## 服务器契约

`POST /api/app/v1/focus/session/pomodoro-study`，需有效登录会话；身份只取 RequestUserContext，禁止请求体指定 userId。

请求必填 `recordKey`（设备随机计时 ID/轮次/本地日期）、`startTime`、`endTime`、`studySeconds`、`creditedSeconds`、`completedRounds`。时长 0–86400 秒、creditedSeconds 不超过 studySeconds、轮次 0 或 1。时间与秒数必须一致，结束不得在未来。幂等键唯一于 `(user_id, client_pomodoro_key)`；同一记录只允许单调增长，重复上报不重复累计。

记录作为 finished study_timer_record 进入现有统计、签到时长和团队统计；完成数只在整轮完成后更新。同步导入增加 `pomodoro_study/upsert` 聚合，沿用导入确认和幂等回执。

## 通知

三端只安排当前阶段的结束提醒。Android 到点取消递减并显示“学习完成/休息完成”，不重排下一阶段；鸿蒙只安排当前阶段一个代理提醒，取消旧版八阶段预排；Windows 发送对应完成气泡。未授权通知时保留计时及页面完成状态，并明确展示能力状态。

鸿蒙 TIMER 实况窗仍按 0145 待审核状态处理，代码和构建成功不代表权益或实体后台验收通过。

鸿蒙专注与番茄的单次 Live View 请求上限为 8 小时，匹配已提交的 TIMER 场景。自定义时长超过该范围时只尝试普通通知和当前阶段代理提醒，并返回动态倒计时能力不足；不调用超出申请范围的实况窗，不据此宣称普通提醒在实体设备一定可用。
