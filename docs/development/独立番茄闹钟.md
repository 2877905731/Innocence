# 独立番茄闹钟

2026-10-16 用户明确要求番茄分页能独立计时，并授权实现后重新发布。此前 0114 / v1.2.4 的“独立分页”实际只有绑定当前专注的阶段倒计时，不能算独立闹钟；本次纠正该实现范围。

- Windows、Android、鸿蒙在“番茄闹钟”分页直接开始，不要求存在活动专注。学习 1–1440 分钟、休息 0–1440 分钟；休息 0 时连续学习。自动循环，用户主动结束，不套用总专注截止点。
- 独立开始、暂停、继续和结束；运行中锁定时长，结束后重新设置。暂停保留毫秒进度。切换分页、导航和总专注暂停/结束都不影响独立时钟。新一轮开始重置本次完成数。
- 时钟使用保存的累计毫秒与参考时刻，后台返回/冷启动按实际时间追赶，不依赖 Flutter 每秒定时器累计。倒拨系统时钟不会产生负时长；与现有专注一样，向前调整设备时间会影响计时。
- SQLite v7→v8 新建 `local_pomodoro_timer(owner_scope PRIMARY KEY, snapshot TEXT NOT NULL)`；按当前本机 ownerScope 或认证 `user:<userId>` 隔离，切换身份先取消旧原生通知。关闭应用保留时钟；退出登录隐藏并取消该身份系统提醒，重新进入同身份时恢复。独立计时只在本机保存，不上传，不自动签到/完成任务，也不重复计入总专注统计。已有专注绑定记录和接口语义保留。
- 原生通道 `innocence/focus_notice.syncPomodoro`：必填 owner/key/active/paused/studyMinutes/breakMinutes/elapsedMs/referenceMs/isChinese。活动 key 必须以当前 owner 的 `/pomodoro/` 开头；校验整数、范围、缺字段与身份不匹配。不开系统通知时传 inactive 清理；本机时钟继续。
- Android 独立持久化、系统阶段闹钟与通知 ID 7305/7306，和原总专注 7302/7303、旧绑定 7304 分离。系统 Chronometer 倒计时；到阶段点更新并继续安排下一阶段，进程不在时仍由 BroadcastReceiver 执行。暂停取消闹钟，继续重建；重启恢复；权限拒绝不取消本机计时，精确闹钟未授权明确提示可能延迟。系统强行停止、OEM 省电与 Doze 完整矩阵仍须真机验证。
- Windows 托盘驻留期间在阶段切换发送对应学习/休息气泡；完全退出后重开追赶，退出期间不会发系统气泡。
- 鸿蒙独立 Live View 7317、普通快照 7318、阶段提醒 7319；不会被原专注结束清理。使用系统代理预排接下来 8 个阶段，前台阶段切换/回到应用续排；受到系统配额及应用权益控制。Live View 不会在 Flutter 冻结时自行切到下一阶段，阶段提醒显示阶段与结束时间。UI 明示预排窗口及动态/后台能力不足，不把此有限预排当无限后台接力。没有权益时保持应用前台，普通通知只显示快照。

鸿蒙 API 依据为本机 API26 SDK 声明与 [OpenHarmony 后台代理提醒](https://github.com/openharmony/docs/blob/master/en/application-dev/reference/apis-backgroundtasks-kit/js-apis-reminderAgentManager.md)。系统权益/配额失败属于能力不足，不伪造动态倒计时。公开 HAP 继续未签名；个人 Profile 与签名材料保留 F 盘私有。

本次无新增服务器接口、无线上数据库迁移/部署。验证与发布记录见后续检查点及 v1.2.5 发行说明。
