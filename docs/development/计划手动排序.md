# 今日与年度计划手动排序

2026-11-24 用户要求 Windows、Android、鸿蒙平板均可直接排序今日任务、年度任务和年度子任务。今日模型为单层任务清单，年度模型为任务及子任务两层；本次不增加日计划嵌套层级。

- 清单提供“排序”入口，打开包含完整清单的排序面板，可拖动手柄或点击上移、下移，点击保存提交。取消不写入，失败保留排序草稿。
- 手动顺序只改变展示顺序；日计划时段、时长、完成状态和任务 ID，年度月份、颜色、进度、子任务内容及 ID 均保持。时间轴仍按时间绘制。月份筛选不产生独立顺序，年度排序面板包含该年全部任务。
- 今日编辑器再次保存须保留清单顺序；今日新任务追加到清单末尾。年度及子任务按现有 `sortOrder` 读取；旧数据沿用原顺序。

## 接口

新增 `PUT /api/app/v1/plans/reorder`，Bearer 解析当前用户，不接受客户端用户归属。请求为 `{scope, planDate?, year?, segmentId?, baseRevision?, items:[{id, revision?}]}`。

| scope | 必填范围 | 并发校验 |
| --- | --- | --- |
| `today` | `planDate`、`baseRevision`、该日全部任务 ID | `dayRevision` 精确匹配 |
| `annual` | `year`、该年全部年度任务 ID 与各自 `revision` | 每个任务 revision 精确匹配 |
| `subtasks` | `segmentId`、`baseRevision`、该任务全部子任务 ID | 父任务 revision 精确匹配 |

成功返回 `data=true`，客户端重新读取对应范围。服务端在单事务中校验完整集合、唯一 ID、归属及版本，之后连续写入 0 起始 sortOrder 并推进日/年度版本。仅改顺序，不调用整日/整任务替换，不触发完成通知。缺字段、非法范围、重复/缺失/外来 ID 或过期版本拒绝，事务无部分修改；认证失败沿用 401，越权父任务沿用 404。无数据库结构迁移。

离线同样在 ownerScope 事务内验证和写入，沿用 daily_plan / annual_segment 快照 outbox 与导入预览、目标账号确认，不新增自动上传。身份切换后旧排序请求不写入新身份的界面。

本功能不调用模型，generation_failure 不适用；保存/读取失败须显示失败并保留草稿。实际验证和三端构建证据见本轮检查点，生产部署、公开发布及实体交互须单独记录。
